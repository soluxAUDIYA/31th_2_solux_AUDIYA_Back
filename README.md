# 🦉어디야 (Audiya)

> 야간 귀가길을 함께하는 안전 서비스

밤길을 혼자 걸어도 불안하지 않도록, **AI 가상 통화**와 **안심 경로**, **음성 기반 위기 감지**로 귀가를 돕는 앱의 백엔드 레포지토리

## 주요 기능

| 기능 | 설명 |
| --- | --- |
| 안심 귀가 | 최단 경로와 안심 경로(밝은 길·CCTV 기준)를 비교해 선택하고, 이동 상황을 추적 |
| AI 가상 통화 | 귀가 중 AI 페르소나와 실시간 음성 통화 |
| 위기 감지 | 경로 이탈, 장시간 정지, 비명, 응급 문구를 감지해 안전 여부 확인 |
| 긴급 알림 | 안전 확인이 안 되면 등록된 보호자에게 긴급 문자와 상황 확인 링크 발송 |

## 기술 스택

| 영역 | 사용 기술 |
| --- | --- |
| 메인 서버 | Spring Boot, Java 21 |
| AI 서버 | FastAPI (Python) |
| 데이터베이스 | MySQL |
| 캐시·토큰 저장 | Redis |
| 인프라 | (배포 환경 확정 후 작성) |

## 브랜치 전략

| 브랜치 | 용도 |
| --- | --- |
| `main` | 배포 기준 브랜치. 현재는 README만 두고, 배포할 준비가 되면 `develop`에서 병합 |
| `develop` | 개발 통합 브랜치. 빌드되고 실행되는 뼈대와 공통 규약이 이 브랜치에 있음 |
| `feature/기능명` | 기능 개발 브랜치. `develop`에서 분기해서 `develop`으로 PR |
| `fix/내용` | 버그 수정 브랜치 |
| `refactor/내용` | 리팩토링 브랜치 |

### 작업 순서

1. `develop`을 최신으로 받는다.
2. 이슈를 생성하고 구현할 기능을 정리한다.
3. `develop`에서 `feature/#이슈번호-기능명` 브랜치를 만든다.
4. 작업하고 커밋한다.
5. `develop`으로 PR을 올린다. (main으로 PR 금지)
6. 코드리뷰 AI의 리뷰 및 팀원들의 코멘트를 반영한다.
7. **Squash and merge**로 병합한다.

`main`과 `develop` 브랜치에는 직접 push하지 않는다.

merge된 원격 브랜치는 삭제하고 로컬 브랜치는 남겨둔다.

## 커밋 메시지 규칙

```
타입: 변경 내용 요약
```

| 타입 | 의미 |
| --- | --- |
| `feat` | 새 기능 |
| `fix` | 버그 수정 |
| `refactor` | 동작 변화 없는 코드 개선 |
| `docs` | 문서 수정 |
| `test` | 테스트 추가·수정 |
| `chore` | 설정, 빌드, 의존성 등 |

예시: `feat: 회원가입 API 구현`

## 개발 도메인

| 도메인 | 내용 | 담당 |
| --- | --- | --- |
| 인증, AI 통화 | 회원가입·로그인, AI 통화, 위기 감지 | 다은 |
| 사용자, 설정 | 사용자 정보, 안전 설정, 비상연락처, 페르소나 선택 | 예은 |
| 귀가 | 귀가 세션, 경로 탐색, 위치 추적 | 서휘 |
| 긴급, 보호자 | 위험 확인, SOS, 보호자 알림 | 지민 |

## 보안 주의사항

DB 비밀번호, JWT 시크릿, 내부 통신 키, 외부 API 키는 **절대 커밋하지 않는다.** 환경변수 또는 `.gitignore`에 등록한 설정 파일로 관리한다.
